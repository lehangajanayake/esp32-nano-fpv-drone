# Shield PCB

The board the XIAO ESP32-S3 Sense plugs into (from below), carrying the four brushed motor drivers, the IMU, reverse polarity protection, battery sense and a status LED.

**Start here:** [docs/shield-pcb-requirements.md](docs/shield-pcb-requirements.md). It holds the outline, stackup, design rules, net classes, placement rules, the full net list and the BOM.

| File | Use |
| --- | --- |
| `docs/shield-pcb-requirements.md` | The requirements to build the schematic and layout from |
| `docs/kicad-build-steps.md` | Step-by-step brief for building the schematic and exporting a readable net list with the KiCad MCP |
| `bom/shield-bom.csv` | JLC-format BOM (Comment, Designator, Footprint, LCSC Part #) |
| `lib/symbols/`, `lib/footprints/`, `lib/3dmodels/` | Project-local libraries (XIAO, custom pads, STEP models) |
| `scripts/` | `gen_schematic.py` captured the first schematic from the requirements; `netlist_md.py` turns the exported net list into `exports/shield-netlist.md` and diffs it against section 5 |
| `exports/` | Schematic PDF and net list exported from KiCad, committed so they can be reviewed on GitHub |
| `production/` | Gerber, drill, BOM and CPL exports for an order (generated, not committed) |

## Creating the KiCad project

1. In KiCad, **File > New Project**, save it in this folder as `shield` (so you get `shield.kicad_pro`, `shield.kicad_sch`, `shield.kicad_pcb` here; untick "Create a new folder").
2. Add `lib/symbols/shield.kicad_sym` and `lib/footprints/shield.pretty` as **project** libraries using `${KIPRJMOD}` paths, so the project works from any clone.
3. Enter the design rules and net classes from sections 2.1 and 6.1 of the requirements in **Board Setup** before routing.
4. Check every item in section 11 of the requirements before freezing the schematic.

## Schematic status (v0.1, 2026-11-26)

`shield.kicad_sch` is captured and matches section 5 of the requirements pin for pin (see the check at the end of [exports/shield-netlist.md](exports/shield-netlist.md)). No PCB yet.

- **ERC: 0 errors, 1 warning, accepted.** `pin_to_pin`: U1 pin 2 (SDx, bidirectional) is on GND, which carries a PWR_FLAG (power output). SDx is tied to GND on purpose because the aux I2C master is unused (section 4.4), so the warning is expected.
- The first version was generated by `scripts/gen_schematic.py` against KiCad 10's standard libraries. From now on **edit `shield.kicad_sch` in KiCad**; re-running the script would overwrite manual edits.
- Project libraries: `shield:DMP2008UFG` (copy of KiCad's DMP3013SFV, same PowerDI3333-8 pinout), `shield:LSM6DS3TR-C` (copy of KiCad's LSM6DS3, same LGA-14 pinout), and footprints `shield:BAT_Pads_3x4mm` and `shield:Motor_Pads_2x3mm` from sections 4.1 and 4.2.
- NT1 uses KiCad's `NetTie:NetTie-2_SMD_Pad2.0mm` (the closest stock net tie to the 1.5 mm in section 6.2).
- The sheet is A3 rather than A4 so the labels stay readable.
- J1, J2, BAT1, MOT1 to MOT4, NT1, TP1 to TP5 and H1 to H4 are excluded from the BOM and position files; every assembled part has an `LCSC` field.

Regenerate the exports after any schematic change (from this folder):

```sh
kicad-cli sch erc -o exports/shield-erc.rpt shield.kicad_sch
kicad-cli sch export pdf -o exports/shield-schematic.pdf shield.kicad_sch
kicad-cli sch export netlist --format kicadxml -o exports/shield.net.xml shield.kicad_sch
kicad-cli sch export bom --fields 'Reference,Value,Footprint,LCSC,${QUANTITY}' --group-by 'Value,Footprint,LCSC' -o exports/shield-bom.csv shield.kicad_sch
python3 scripts/netlist_md.py
```
